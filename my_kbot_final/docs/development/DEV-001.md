# DEV-001：基础服务与系统状态页

状态：已验收（2026-10-20）。此状态仅覆盖本任务，不代表整个 Final 项目完成。

## 目标与分工

从独立 Go 模块启动一个连接真实 PostgreSQL 的 HTTP 服务，并在 Web 控制台看见存活与就绪状态。

- 学习者：配置、数据库连接池、Chi 路由、健康检查处理函数、启动装配与优雅关闭。
- 助手：测试、最小 Web 控制台、请求层适配、响应式布局、联调和文档。

参考基线：Q1mi/kbot 提交 `baed6c354e1966cdae7bc5328e771dc50ae6c70b` 的 `kbot-final`。前端沿用 React、TypeScript、Vite、Ant Design、Wouter、TanStack Query、Axios 的组合，按已完成的后端能力逐步接入。

## 接口约定

`GET /healthz` 成功返回 HTTP 200、文本 `ok`；不检查数据库。

`GET /readyz` 在请求 context 派生的 2 秒期限内检查依赖。全部成功返回 HTTP 200、文本 `ok`；首个失败返回 HTTP 503、文本 `not ready: postgres`。错误细节不直接输出给前端。

状态页通过同源 Vite 代理调用这两个接口。只有 HTTP 200 且正文去掉空白后为 `ok` 才判定正常，避免误把 HTML 回退页当作健康响应。非 200、超时和连接失败分别保留可辨认的状态。取消请求交给 Query 管理。

## 实施与运行链

1. 配置加载、校验，启动本项目的独立 PostgreSQL 容器。
2. `postgres.Open` 创建池并 Ping；启动失败则返回错误。
3. 主程序将 `pool.Ping` 注入 Handler，再注册 Chi 路由。
4. 信号 context 与监听错误通道共同控制服务生命周期。
5. Web 状态页调用检查 API，展示整体结果和每项 HTTP 状态、耗时；支持手动刷新。

详细模块图、启动和验证命令见 [README](../../README.md)。
