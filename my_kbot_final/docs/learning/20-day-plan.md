## 时间与范围

- 学习者已确认每天可投入 3–4 小时，按此安排有效学习任务；包含阅读、手写、追问、调试和联调，不能只计算复制代码的时间。
- “第 N 天”指第 N 个有明确验收的学习日，不绑定固定日期。目标是 20 个学习日完成首轮核心闭环；实际自然日跨度和完成速度以记录为准，不承诺必然 20 个自然日完成。
- 学习者编写 Go/SQL 生产代码；助手维护测试、脚本、前端、接口联调、README 和阶段依赖图。每轮围绕一个小功能；按学习者最新要求，相似 SQL、映射和简单包装可以合并给出，新机制仍单独解释。

- 这不等于原版 Final 所有模块逐行复写完成。高级模块明确放到后续清单；不得将当前目标偷换成“整个 Final 已完成”。

## 每天如何判定完成

当天必做项全部满足，才记录“已完成”：

1. 学习者的代码已经保存，相关包能够编译，当前行为测试通过，主要错误分支有验证。
2. 涉及持久化的功能使用真实 PostgreSQL 验证；使用假模型、假沙箱或真实 Docker 的范围分别记录，不能互相冒充。
3. 当天涉及界面的，助手完成对应最小页面并用浏览器联调；纯类型、SQL 或存储步骤不为展示进度而硬加页面。
4. 对本轮关键调用链已经讲解、追问中的主要误解已澄清；不要求额外考试，也不以机械背诵作为通过条件。
5. 助手更新 progress.md，列出已验收证据、未完成事项和下一起点。在阶段节点更新 README、依赖图并给出 Git 提交命令，由学习者提交。

收工时统一给出：**“第 X 天任务完成。已验收：……；下次从第 X+1 天的……开始。”** 若没通过则明确说“第 X 天尚未完成，还差……”，不因给出了一段代码或到了晚上而判定完成。

用户说“继续”时默认继续当前日的第一个未完成项。一天验收完成后停止加新任务；用户明确要求再推进才开始下一日。用户提前结束时记录断点，下次接着做，不把中断算成完成。
